2. Multi-Tenant Workspace Isolation

Every league administrator has their own isolated tournament without cross-contaminating other organizers:

How Multi-Tenancy Functions:

  1. Provisioning (/superadmin/create-admin): When Superadmin provisions an account (e.g., Mansha), the system creates a dedicated tournament space: auction_mansha_<timestamp> with 0 teams, 0 players, and default "All" category.
  2. Case-Insensitive Authentication: The login query checks LOWER(TRIM(username)) = LOWER(TRIM($1)). Signing in as Mansha, mansha, or MANSHA succeeds reliably.
  3. Automatic Workspace Self-Healing: If an older admin account lacks an assigned tournament, data.ensureAuctionForUser() automatically generates their blank tournament on their very first login.
  4. Master Organizer Preservation: System administrators (anurag and admin) maintain their master tournament (active_auction) with all 66 franchises and 1563 registered players.

3. Database Resilience & Zero-Downtime Failover

To eliminate 502 Bad Gateway responses when remote PostgreSQL instances experience network blocks, models/data.js implements a resilient query adapter:

// models/data.js - Connection Safety & Query Routing
const poolConfig = {
    connectionTimeoutMillis: 2000, // 2s Connection Timeout
    idleTimeoutMillis: 5000,
    query_timeout: 2500,           // 2.5s Query Timeout
    statement_timeout: 3000
};

const dbAdapter = {
    async query(sql, params = []) {
        if (isPgConnected && pgPool) {
            try {
                return await pgPool.query(sql, params);
            } catch (pgErr) {
                console.warn('[PostgreSQL Query Fallback to SQLite]:', pgErr.message);
            }
        }
        // Fall back to SQLite auction.db with 100% reliability
        const sdb = await getSqliteDb();
        const sqliteSql = sql.replace(/\$\d+/g, '?');
        return await sdb.all(sqliteSql, params);
    }
};
